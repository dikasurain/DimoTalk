## 一、项目概述

滴墨讲（DimoTalk）是一个基于"用户-设备-用户"架构的语音交流系统：用户通过硬件设备进行语音输入，经语音识别与 TTS 分析处理后，传递给另一端用户完成语音输出，实现跨设备、跨用户的实时语音交流。

## 二、整体架构

架构主线：**用户 - 设备 - 用户**

```
用户A（语音输入）──> 硬件设备 ──WiFi局域网──> 下位客户端程序 ──> 上位处理（识别/TTS）──> 硬件设备 ──> 用户B（语音输出）
```

当前软件分为两部分：
- **上位程序**：负责业务功能（语音识别、方言、模仿、TTS 分析等）。
- **下位程序**：负责与硬件设备的 WiFi 接入通信（本次扩展重点，主要定位为客户端，不排除后续以服务端模式运行的可能）。

## 三、功能描述（上位程序）

### 3.1 语音识别模块
- **输入**：采集用户原始语音，进行降噪、分帧等预处理后送入识别引擎。
- **输出**：将识别结果转换为文本/指令，供后续 TTS 分析与业务层使用。
- **方言**：支持方言语音识别，将方言转换为标准文本。
- **模仿**：支持对说话人音色、语气的模仿，在输出侧还原个性化语音。

### 3.2 用户挂起
- 用户首先可将设备置于**挂起**状态，暂时中断语音链路。
- 挂起期间设备保持网络连接，可随时恢复，无需重新配网。

### 3.3 TTS 分析
- 用户语音经识别后，通过 TTS 分析生成合成语音并输出。
- 结合"模仿"能力，输出语音可保留原说话人的音色特征。

## 四、下位程序（硬件 WiFi 接入）

> 本部分为当前扩展重点，后续将配合硬件 WiFi 接入程序逐步完善。
> 角色定位：**客户端**（下位程序主动发现并连接硬件设备/网关）。

### 4.1 角色与职责
- 下位程序作为客户端运行，通过 WiFi 局域网主动发现并连接硬件设备。
- 硬件设备作为接入节点，负责语音数据的采集与播放。
- 下位程序承担上位业务层与硬件之间的数据转发桥梁。

### 4.2 设备发现
- 基于 UDP 广播 / mDNS 在局域网内发现硬件设备。
- 提供设备列表展示与设备信息（名称、IP、固件版本）读取。

### 4.3 连接管理
- **控制通道**：TCP 长连接，负责指令交互与状态同步。
- **音频通道**：UDP，负责实时语音流的双向传输。
- 心跳保活、断线检测与自动重连。

### 4.4 通信协议（草案）
- 控制指令：JSON 文本帧（连接、挂起、恢复、音量调节等）。
- 音频数据：二进制帧（帧头 + 序号 + 时间戳 + PCM/压缩音频数据）。

### 4.5 与上位的接口
- 下位程序将收到的音频流送入上位语音识别模块。
- 上位 TTS 输出经下位程序下发至硬件设备播放。
